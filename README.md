# Student Finance

Простое приложение для учёта личных доходов и расходов. Русский интерфейс, адаптивный дизайн, без регистрации, сервера, сборки и внешних ресурсов. Работает без интернета.

## Как запустить без знаний программирования

1. На странице репозитория GitHub нажмите зелёную кнопку **Code**, затем **Download ZIP**.
2. Распакуйте скачанный ZIP-архив целиком: в Windows — правой кнопкой → «Извлечь всё», на macOS — двойным щелчком по архиву.
3. Откройте распакованную папку `student-finance-main` и дважды нажмите **index.html**. Если система спросит, выберите Chrome, Edge, Firefox или Safari актуальной версии.
4. Готово. Ничего устанавливать и вводить в терминале не нужно. Оставьте `index.html`, `styles.css`, `finance.js` и `app.js` в одной папке.

Чтобы открыть приложение снова, откройте **тот же файл в том же браузере и профиле**. Можно добавить страницу в закладки. Не запускайте её из нераспакованного архива и не используйте приватный режим для постоянного хранения.

## Как пользоваться

- Выберите «Расход» или «Доход».
- Введите сумму: `350`, `350,50` или `350.50`. Укажите категорию из подсказок или напишите свою и выберите дату. Нажмите «Добавить операцию».
- Вверху появятся общий баланс, доходы и расходы за всё время. История отсортирована по дате, новые записи одной даты идут первыми.
- Нажмите «Редактировать» рядом с нужной записью. Измените поля и нажмите «Сохранить изменения». Кнопка отмены оставляет запись без изменений.
- Нажмите «Удалить» и подтвердите действие в окне. Баланс пересчитается автоматически.

Суммы должны быть больше нуля и содержать не более двух знаков после запятой. Буквы, отрицательные числа, пустые суммы, дроби копейки и экспоненциальная запись отклоняются. Максимум одной операции — **999 999 999,99 ₽**. Дата должна существовать и быть не раньше 1900 года; будущие даты разрешены. Категория — от 1 до 60 символов. Отрицательный итоговый баланс допустим.

## Хранение и ограничения

Данные автоматически сохраняются в `localStorage` браузера, а не отправляются в интернет. Расчёты ведутся в целых копейках. Если сохранение не удалось, приложение сообщает об ошибке и не применяет изменение. Если сохранённая история повреждена, запись блокируется, исходные данные не перезаписываются.

- Данные привязаны к браузеру, профилю и адресу страницы. Не переносите и не переименовывайте папку приложения после начала использования: доступ к прежней истории может пропасть.
- Поведение `localStorage` для локальных файлов зависит от браузера. Если он запрещает хранение для `file://`, используйте другой актуальный браузер либо локальную раздачу файлов, описанную ниже. Приложение не обещает сохранность при политике, запрещающей такое хранение.
- Очистка данных браузера, удаление профиля и завершение приватного сеанса могут удалить историю. Автоматического резервного копирования, импорта/экспорта, синхронизации между устройствами и шифрования нет. Для критически важных данных храните отдельную копию вне приложения.
- На телефоне удобнее открыть приложение по постоянному адресу на статическом хостинге; установка на телефон и синхронизация с компьютером в эту версию не входят.
- Между вкладками одного адреса изменения подхватываются автоматически. Одновременные правки не объединяются: более позднее сохранение может заменить предыдущее.
- История целиком находится в памяти и `localStorage`. Это приложение для личного бюджета, без пагинации больших архивов и поддержки нескольких валют.

## Для разработчика

Стек: HTML, CSS, обычный JavaScript. Приложению не нужны Node.js, npm, Python или зависимости. `finance.js` содержит расчёты, валидацию и хранение; `app.js` — интерфейс.

### Тесты логики

Требуется Node.js 18 или новее. В папке проекта:

```sh
node --test tests/finance.test.cjs
```

11 тестов: суммы и копейки, неверные значения, добавление/редактирование/удаление, отрицательный баланс, категории и даты, идентификаторы, сохранение/чтение, повреждение данных, отказ хранилища, безопасные пределы итогов и форматирование.

### Браузерная проверка (необязательно)

Это отдельный инструмент разработки, он не нужен пользователю приложения. Установите Playwright вне репозитория, например, в Linux:

```sh
npm install --prefix /tmp/student-finance-browser --cache /tmp/student-finance-npm-cache --no-package-lock playwright
NODE_PATH=/tmp/student-finance-browser/node_modules node tests/browser.cjs
```

Скрипт по умолчанию использует Chromium `/usr/bin/chromium`; путь можно изменить переменной `BROWSER_PATH`. Если политика браузера запрещает локальные файлы, запустите в папке проекта:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

В другом терминале из той же папки:

```sh
TEST_URL=http://127.0.0.1:8765 NODE_PATH=/tmp/student-finance-browser/node_modules node tests/browser.cjs
```

Браузерные проверки создают изолированный профиль, проверяют интерфейс и сохранение, делают снимки экрана в `/tmp/student-finance-desktop.png` и `/tmp/student-finance-mobile.png`. Персональные данные вашего обычного браузера не затрагиваются. Локальную раздачу файлов остановите сочетанием Ctrl+C. Для обычного использования через локальный HTTP открывайте один и тот же адрес: смена порта создаёт отдельное хранилище.

В облачной среде проверены Chromium, интерфейс 1280 px и 375 px, добавление, изменение и отмена, подтверждение и отмена удаления, баланс, валидация, перезагрузка и повторное открытие вкладки, отказ сохранения и повреждённые данные. Прямой запуск `file://` в облачном браузере заблокирован административной политикой, поэтому этот способ здесь не проверен. Другие браузеры и физические телефоны не проверялись.
